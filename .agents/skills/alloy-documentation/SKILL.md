---
name: alloy-documentation
description: Guides documentation changes in Alloy. Use when documenting prototypes, findings, architecture, or design research.
---

- Document meaningful findings, not every code change: bottlenecks, API decisions, and validated architecture.
- Keep prototype documentation in `docs/prototype/`.
- Reserve the root of `docs/` for architecture, core design, and research documents.
- Update existing documents where possible; avoid redundant notes.
- Prefer mermaid diagrams over asci diagrams wherever diagraming is needed to define architecture or design.
- While documenting ideations, vision and reserach do not assume anything unless it's explicitly said. If unclear on how certain thing is achieved or we are planning to architect, mention probable solutions explicity in the docs instead of assuming we are going to use certain architecture decision
- Check for discrepencies and irregularies across documention and report the author
